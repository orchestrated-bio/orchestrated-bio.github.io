The gate

Verification is a script, not an assurance.

A case is not product-grade because the prose reads well. It is product-grade when verify_product_case.sh passes, and it fails closed.

All eight modules must exist. Each needs its own search log. Every identifier must resolve, every artifact must be on disk, and semantic verification must find no unresolved defect where a module says something its source does not. The rendered site must exist and survive an offline audit for stale claims and broken links.

The report is then bound to a manifest hash and a git commit, so the version you read is the version that passed. You can re-run the gate yourself.

What the gate does not do. It checks that the work is traceable, not that the judgment is right. Machine verification cannot tell you a conclusion is wise. That is what the reviewer attestation is for, and the signoff field on every case we have published is currently null.
